# Portfolio Repository Structure

Your portfolio is the **main artifact** of the program. It's where you showcase your work and where mentors evaluate your progress. Set it up in Week 1 and keep it updated every week.

---

## Step 1: Create Your Repository

Create a new GitHub repository named: `your-name-portfolio` (e.g., `jane-doe-portfolio`).

Make it public so mentors and peers can view it.

---

## Step 2: Add This Structure

Create these five folders in your repo:

```
your-name-portfolio/
├── engineering-notes/    # Your SDLC, Agile, Git notes (Week 2+)
├── ai-learning/         # AI concepts, prompts, experiments (Week 8+)
├── mini-projects/       # Small projects from the curriculum
├── system-design-notes/ # Architecture diagrams, designs (Week 4+)
└── experiments/         # Code experiments and prototypes
```

You can add a README or placeholder file in each folder so Git tracks them. Empty folders don't get committed.

---

## Step 3: Write Your README

Your README should include:

1. **Your name**
2. **Program:** Otic Agentic AI Academy
3. **Link to this curriculum** (this repo)
4. **Weekly Work table** (see below)

---

## Step 4: Add the Weekly Work Table

This is the most important part. Each week, add a row linking to that week's deliverable.

Copy this template and paste it into your README:

```markdown
## Weekly Work

| Week | Topic | Link |
|------|-------|------|
| 1 | Onboarding | [Portfolio setup](.) |
| 2 | Foundations | [Engineering notes](engineering-notes/) |
| 3 | Best Practices | [Refactored code](link-to-your-repo) |
| 4 | System Design | [AI Career Assistant design](system-design-notes/) |
| 5 | Software Architecture | [API + deployment](link-to-deployed-url) |
| 6 | UX/UI Design | [Wireframes](link) |
| 7 | Quality Assurance | [Test suite](link) |
| 8 | AI Foundations | [AI assistant](link) |
| 9 | AI Reliability | [Evaluation framework](link) |
| 10 | Team Development | [Team product](link) |
| 11 | AI for Africa | [Community project](link) |
| 12 | Capstone | [Capstone repo](link) |
```

**Update this table every week.** Replace `link` with the actual URL to your work—a repo, deployed app, Figma file, or doc. If something lives in this portfolio repo, use a relative link like `[Engineering notes](engineering-notes/)`.

---

## Why This Matters

- **For you:** One place to see everything you've built. Useful for job applications.
- **For mentors:** We use your portfolio to track progress and give feedback.
- **For the program:** It's a requirement. All weekly work must be linked from your portfolio.
